# Changelog

## Unreleased

### ⚠ BREAKING CHANGES

* **files:** a stored file's part keeps the version's address, which works only with authorization, instead of a download link: a task, a checkpoint and a session hold no credential. The server puts a download link in its answers and push notifications on behalf of the caller's usage attribution, and an agent reads a file with `read()` or `link()` of `ConversationFile`, or through `inline_files`; code that fetches `part.url` itself, or hands it to a model, gets no file.
* **adk:** `emit_artifact` is a plain function and takes no invocation context, `emit_artifact(emitter, artifact, ...)`, as in LangGraph: it never awaited anything nor used the context, and `await emit_artifact(emitter, ctx, artifact)` no longer works.
* **adk:** the first argument of `emit_message` is `message`, not `text`, as it takes an iterator of text as well; a call that names it `text=` fails.
* **adk:** an async iterator given to `Thread.reply()` or `Thread.post()` streams text only: an ADK `Event` it yields is left out with a warning instead of becoming a chunk, which sent the model's thoughts and the text of ADK's final event as the answer.
* **langgraph:** a model of the SDK called without `await` - `invoke()` or `stream()` - inside an `async def` node, or `inline_files_sync()` there, fails the task at once on a message with a file to read, with a reason that says to call `ainvoke()` or `astream()`, or to call the model from a synchronous node. It runs on the turn's event loop, which cannot read the file while it waits: such a call fetched the file's address, which refuses a request without authorization, and failed every turn after the one that brought the file, while holding the server for up to 30 s. A call without a file still goes to the model, and the first one in the process logs a warning: it holds every turn of the server until the model answers.

### Features

* **adk:** `emit_message` streams an iterator of text, and the new `aemit_message` an async iterator of text as well, as one section of the streamed answer, ended by the complete `Event` they return; for text, `emit_message` and `Thread.post()` return the `Event` they sent, and `Thread.post()` returns the one that ended the section of an iterator.
* **langgraph:** `emit_message` takes text as well, as a message, and streams an iterator of `str` or `AIMessageChunk`, `llm.stream(...)` say, and the new `aemit_message` an async iterator as well, `llm.astream(...)`: the iterator goes out as one section of the streamed answer, and the whole message that ends it is returned for the node to keep in its state. The model calls that start while the iterator is read stay off LangGraph's `messages` stream, so the answer goes out once.

### Bug Fixes

* **server:** a turn that ends the task with a `Task` in the outbox (`COMPLETED`, `FAILED`, `CANCELED`, `REJECTED`) sends its push notification with that Task and ends its execution; the callback received only `SUBMITTED`, and the task stayed held by the server.
* **langgraph:** a state field declared as `Optional[A2AOutbox]` or `A2AOutbox` is kept out of the checkpoint, as `A2AOutboxField` is: the server gives it LangGraph's untracked channel in the graph it serves, so LangGraph no longer warns that it will refuse to load `aion.core.a2a.models.A2AOutbox`. A compiled graph the server copies keeps the msgpack allowlist LangGraph built from its state schema.
* **files:** download links of stored files are issued on behalf of the caller's usage attribution: the answer to a message and its stream with the message's, a read (`GetTask`, `ListTasks`, `GetContext`, `SubscribeToTask`, `CancelTask`) with the one it declares in `A2A-Extensions` and `Aion-Usage-Attribution`, and a turn's push notifications with that of the message whose turn it is, so they carry working links, which the Files API refuses to issue for the deployment's daemon.
* **files:** a download link is handed out only on behalf of the usage attribution it was issued to, never to another caller or to the deployment's daemon, and a link refused to one of them no longer keeps another from asking for its own.
* **server:** `aion.server.tasks` and `aion.server.contexts` can be imported before any other module of the server; they failed with a circular import.
* **files:** a stored file the storage does not make available to the sender of a turn - one another participant of a shared conversation stored, say - no longer fails every turn that has it in its history: `read()` and `link()` of `ConversationFile` and the conversation's reads raise `ConversationFileForbiddenError` without fetching its address, and the SDK's models and `inline_files` leave it out with `[File "a.pdf" (application/pdf) is not available to this sender and was left out]`.
* **files:** a file whose address refuses a read is reported with what the address answered - it refused access, or no longer serves the file - instead of a download link that may have expired.
* **server:** the push notifications of a turn ask for file links on behalf of the request whose turn it is, a message queued into a running task included, instead of the request that started the task's execution on the server.
* **server:** a cancel runs with the usage attribution its request declares and sends, so what the executor does while cancelling - reading or storing files - is done on the canceller's behalf instead of the deployment's daemon.
* **files:** a part an agent sends with a stored file's address and no `aion:file` reference - an ADK `file_data` part, a LangGraph URL block - gets the reference back, so the client receives a working download link instead of an address that never downloads.
* **files:** a conversation whose history holds a file that is no longer stored - past the 30 days the SDK stores a conversation's files for, or removed earlier - no longer fails every later turn: `read()` and `link()` of `ConversationFile` and the conversation's reads raise `ConversationFileRemovedError` without fetching its address, and the SDK's models and `inline_files` leave it out with `[File "report.pdf" (application/pdf) is no longer available and was left out]`.
* **files:** content a turn read from a stored file is no longer stored again when it reaches the framework's state - a LangGraph graph that returns the messages `inline_files` gave it, an ADK tool that returns the bytes of a file it read: the checkpoint or the session links the stored file it came from, with its retention, instead of gaining a new copy of every such file on every turn.
* **models:** a file Aion's model service refuses is left out with a note on LangGraph, where the call failed with `APIError`, and on ADK whatever the provider's words: the service reports a provider's refusal as the `api_error` event of its stream, with HTTP 200, and the SDK reads the provider's status from the start of its message. The request that checks one file alone is streamed, since the service answers only with a stream: a file the model takes is no longer left out with those it refused, and on ADK such a request no longer fails.
* **models:** a call to Aion's model service without a stream no longer fails: the service answers every request with a stream, which `ChatOpenAI` and LiteLLM could not read as the answer to a request without one. The SDK's models stream every request, and a call without a stream - `invoke()` outside a run that streams the graph's messages, the agent behind an ADK `AgentTool` - gets the answer the chunks make.
* **models:** a file of a model request is known by its stored file wherever the turn knows it - a file of the message in ADK's run request, which names it by an address the session does not name, and the bytes a request carries: a tool's media, a LangGraph block `inline_files` gave the graph - so a file the model refused in one turn is left out in the next, and the warning names the stored file instead of `not stored`. The same bytes with another media type are another file.
* **models:** a request with tools through `aion_lite_llm` no longer fails before it is sent in a project with both frameworks installed: LiteLLM 1.103 and later load their MCP gateway for every request with tools, and the gateway needs an `mcp` release `langchain-mcp-adapters` does not allow. `aion_lite_llm` skips the gateway, which serves only MCP tools that name LiteLLM's proxy.
* **langgraph:** an answer `thread.reply()` or `thread.post()` streams from a model - its `astream()`, or text taken from it - reaches the client once: LangGraph streamed the model call on its own as well, and a second section started the answer over. The model calls that start while the thread reads the iterator stay off the graph's `messages` stream, so what the iterator yields is the answer, with the reply's routing target, and a model call the iterator makes for itself does not reach the client. A call that started before the thread reads the iterator, or one given `tags` in a config of its own, still streams on the graph.
* **langgraph:** the whole message that ends a section `thread.reply()`, `emit_message` or `aemit_message` streamed takes the id its chunks share, so a model's stream that LangGraph streams as well - an iterator read before it was passed to them - no longer reaches the client a second time as a message.
* **langgraph:** a node that emits the chunks of a model call itself - `for chunk in llm.stream(prompt): emit_message(writer, chunk)` - or the message the call returned no longer sends the answer twice: LangGraph streams the call on its own as well, and the server now leaves out the node's copy, with the routing target and metadata it gave the chunks.
* **server:** a push notification the webhook does not acknowledge is tried again: a timeout, a failed connection, HTTP 408, 429 and 5xx get up to five more attempts, after 1, 2, 4, 8 and 16 s, or after the receiver's `Retry-After` up to 16 s; a delivery that gives up is logged as a warning, and the task's outcome counts as pushed only once it is queued, so an outcome that never reached the sender is still pushed when the execution ends. Each webhook receives a task's events in order from a queue of its own, so the stream, `message/send` and a cancel no longer wait for the webhook.
* **files:** a stored file read while the storage service is unavailable for a moment - an error worth retrying, or no link within five seconds - raises the new `ConversationFileUnavailableError` without fetching the file's address, and the SDK's models fail the turn with it as the reason. The failure is remembered for five seconds, not a minute: every read of the file in that minute, its owner's included, fetched the address and failed with `The address refused access`, and so did reads right after the service was back.
* **server:** the SDK runs on a2a-sdk 1.3.1, pinned exactly: the metadata of a `CancelTask` request reaches `AgentExecutor.cancel`, a cancel that fails no longer writes over a task's outcome, the queues of a task whose execution fails to start are closed, a message that names only a task is given the task's context, and a v0.3 call with invalid params is answered with `-32602`. A Task an agent ends the task with from its outbox has its outcome applied through a2a-sdk's event consumer, which now drops a status update for a task that is terminal already, so that outcome is still pushed. a2a-sdk's plugins (`a2a.plugins`) are not run by the server.
